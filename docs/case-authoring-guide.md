# 精制案件内容填写指南

本文件供内容编辑使用，描述每个精制版案件需要填写的字段及填写规范。
填写完成后，将数据按照 `scripts/case-template.ts` 的骨架写入 `src/data/cases-extended.ts`，
然后运行 `npm run check` 验证无断链、构建通过。

---

## ⚠️ 核心原则：不把答案写进勘查或选项

**勘查阶段只给事实，结论留给玩家。**
**断案选项只写标签，理由放到复盘。**

如果内容编辑只看断案选项就能猜出正确答案，说明选项泄题，需要重写。
如果玩家不做推理、只读勘查文本就能知道真相，说明勘查直给，需要重写。

---

## 一、案件基本信息（填入 `cases.ts` 的 seed 数据）

| 字段 | 说明 | 示例 |
|---|---|---|
| `id` | 两位数字，与原案件编号一致 | `'01'` |
| `title` | 案件标题，4-6 字 | `'梁上白绫'` |
| `subtitle` | 一句话副标题 | `'一根旧绫，一场精心布置的自尽'` |
| `difficulty` | `'入门'` / `'进阶'` / `'高阶'` | `'进阶'` |
| `category` | 见下方类型表 | `'伪装自杀'` |
| `playerTask` | 玩家在勘查阶段的目标句 | `'查明赵氏死亡真相，找出谁在撒谎'` |

**案件类型（category）**：
`伪装自杀` / `动机排除` / `身份推理` / `路线时间` / `密室现场` / `物证翻案` / `机关诡计` / `文字谜` / `连环预告`

---

## 二、表面故事与真实故事

### 2.1 表面故事（`intro` 数组，3-5 段）

- 以第三人称叙述官方/报案人的说法
- 包含时间、地点、人物、表面死因
- 不暴露任何矛盾，让玩家产生"看起来合理"的第一印象
- 每段 60-120 字

### 2.2 真实故事（`solution.truth` 一句话 + `solution.reasoning` 3-5 条）

- `truth`：一句话揭示真相，30 字以内
- `reasoning`：逐条推理链，从"表面可疑点"到"关键物证"到"结论"
- 每条 20-50 字

### 2.3 现代读者小注（`readerNote`）

- 说明案件的历史/文化背景，帮助现代玩家理解
- 不超过 80 字

---

## 三、证据列表（`evidenceList`）

每案建议 6-9 条证据，比例参考：
- `key`（关键证据）：3-4 条，每条直接支撑真实结论
- `supporting`（辅助证据）：1-2 条，加强某个推论但不单独成立
- `context`（背景信息）：0-1 条，帮助理解案情但不直接参与推理
- `decoy`（误导证据）：1-2 条，**必须有**，否则推理无挑战性

### 字段说明

```
id        唯一标识，用小写英文+连字符，如 torn-clothes
title     证据名称，4-8 字
content   证据描述，20-50 字，说明玩家"看到了什么"，不包含结论
role      key / supporting / context / decoy
supports  （可选）该证据支撑哪些推论标签，用于内容自查
misleadsTo（可选）decoy 类证据会把玩家引向什么错误结论
```

### 证据文本写法

**content 只写客观事实，不下结论：**

❌ 错误写法：`双脚离板凳过远，难以自己蹬翻完成上吊。`
（"难以自己蹬翻完成上吊"是结论，不是事实）

✅ 正确写法：`赵氏双脚与倒地板凳相距约三尺，板凳倒向西侧，绳结距梁约一臂。`
（给位置、数量、方向，让玩家自己推理）

### 误导证据设计要点

- 误导证据必须"表面合理"——如果玩家一眼就能排除，就没有迷惑性
- 误导证据必须"有破绽"——复盘时能解释为什么它不成立
- 每个 decoy 必须填写 `misleadsTo`，便于复盘警示引用
- **误导证据应能形成一条完整但错误的推理链**（见第九节：红鲱鱼链）

## 四、调查节点（`investigationNodes`）

每案建议 6-9 个节点，总行动点成本控制在 `actionPointLimit - 1` 到 `actionPointLimit + 1` 之间。

### 字段说明

```
id        唯一标识
type      scene（现场）/ witness（证人）/ evidence（物证）/ timeline（时间线）/ knowledge（知识）
title     节点名称，玩家点击前就能看到，6-12 字
prompt    （可选）追问类节点显示的前置说明，让玩家知道他在追问什么
result    调查后展示的内容，40-100 字，客观描述，不直接给出结论
cost      行动点消耗，通常为 1；高价值节点可设为 2
requires  （可选）前置节点 id 列表，须先解锁这些节点，本节点才出现
unlocks   （仅注释用）本节点解锁后"逻辑上会引出"哪些节点，不参与 UI 计算
evidenceIds（可选）本节点关联的证据 id，解锁后这些证据可在断案阶段勾选
```

### 勘查文本禁用词 / 谨慎词

以下词语在 `result` 中使用时需要特别谨慎，容易把结论直接送给玩家：

| 禁用/谨慎 | 说明 | 替代方向 |
|---|---|---|
| **说明** | 直接给结论 | 改为客观描述，让玩家自己"说明" |
| **证明** | 同上 | 只描述事实，结论留给断案 |
| **即栽赃** | 直接命名结论 | 改为"血印位置与握刀姿势之间存在矛盾" |
| **真正目标** | 剧透意图 | 改为描述行为事实，让玩家推动机 |
| **最可能** | 引导结论 | 移到复盘反馈 |
| **只有……才……** | 独断句式 | 改为"已排除 A 和 B，剩余可能是 C" |
| **无法成立** | 判断性结论 | 描述具体矛盾，不直接判断 |
| **不可能** | 同上 | 描述物理/逻辑约束事实 |

**例外**：知识类节点（`type: knowledge`）可以在解释原理时使用结论性语句，因为玩家主动"查阅知识"时期望得到明确答案。但即使如此，建议给出结论的同时呈现 2 个互相竞争的解释，再让玩家在断案时选择。

### 行动点设计原则

- `actionPointLimit` 建议设为"最优路径总花费 + 1-2 点"
- 玩家走最优路径（调查所有关键节点）仍有 1-2 点容错余地
- 玩家误查 1-2 条误导节点后，仍能形成最低限度的推理链
- 入门案：8-10 点；进阶案：10-12 点；高阶案：12-14 点

### 节点可见性规则（重要）

- `requires` 是节点显示的**唯一**判断规则，UI 只看 `requires`
- `unlocks` 仅是内容设计标注，不参与 UI 计算
- 追问节点（需要先解锁父节点）必须填 `requires`

## 五、推理步骤（`deductionSteps`）

固定 4 步，顺序为：

| 步骤 | 类型建议 | 目的 |
|---|---|---|
| step-surface | `single` | 玩家判断表面说法是否可信 |
| step-contradiction | `single` | 找到最核心的逻辑矛盾 |
| step-evidence | `multi` | 组合支撑推论的多条证据 |
| step-conclusion | `single` | 给出最终结论 |

### 字段说明

```
id                唯一标识，建议用 step-surface / step-contradiction / step-evidence / step-conclusion
prompt            问题文本，20-40 字
type              single（单选）/ multi（多选）/ text（文本，有内容即满分）
options           选项列表，single/multi 类型必填，每个选项有 id 和 label
correctOptionIds  正确答案 id 列表（single 填 1 个，multi 填多个）
requiredEvidenceIds（可选）答对该步骤需要已发现的关键证据，用于评分倍率（0.6 + 0.4 * 命中比例）
maxScore          该步骤满分，建议：step-surface=2，step-contradiction=2，step-evidence=3，step-conclusion=3
```

### 选项设计要点（核心反猜答案规则）

**选项只写中性短标签，不写理由，不写"正确/错误"。**

❌ 错误写法（选项自带结论）：
```ts
{ id: 'infiltrate', label: '潜入京城另有图谋——最能解释全部行为' }
{ id: 'war', label: '挑起战火——杀使团已足够，无需冒充进京' }
```

✅ 正确写法（中性短标签）：
```ts
{ id: 'infiltrate', label: '借身份潜入京城' }
{ id: 'war', label: '挑起边境战乱' }
{ id: 'reward', label: '冒领赏赐贡礼' }
```

**理由放到 `feedback.optionFeedback`，复盘时再解释。**

验收标准：
- 遮住勘查内容只看选项，不能明显看出哪个是正确答案
- 错误选项也要有表面合理的支撑（否则玩家可以排除法猜中）
- 正确选项不比错误选项长一大截
- `single` 类型建议 3-4 个选项；`multi` 类型建议 4-5 个选项，正确占多数，混入 1 个误导

## 六、阅卷初判（`initialHypotheses`）

3 个选项，玩家在**阅卷阶段**（读故事后、开始调查前）选择第一印象。

```
id        唯一标识
label     选项文字，10-20 字
feedback  结案后复盘时展示的反馈，说明该初判为何成立或为何偏差，30-60 字
```

设计原则：
- 1 个与真实答案接近（但不完全一样）的选项
- 1 个指向最常见误解（通常是表面故事的说法）
- 1 个模糊/中性选项

---

## 七、复盘反馈（`feedback`）

### 7.1 选项反馈（`optionFeedback`）

为 `deductionSteps` 中**每个选项 id** 写一条反馈文字（包括正确和错误选项）。

- 正确选项：说明"为什么这是对的"，引用 1-2 条证据
- 错误选项：**先承认这个答案为什么看起来合理，再指出哪里断了**，不要直接说"你错了"

### 7.2 证据反馈（`evidenceFeedback`）

为 `evidenceList` 中**每条证据 id** 写一条反馈文字。

- key 证据：说明它在推理链中的作用
- decoy 证据：**先承认它为什么表面合理，再解释为什么它实际不成立**

### 7.3 漏掉关键证据提示（`missingKeyEvidence`）

为 **key 类证据**写一条"玩家漏掉时的提示"，帮助玩家在复盘中理解自己错过了什么。

### 7.4 总结文字（`finalSummary`）

```
excellent  得分率 >= 80% 时显示，肯定玩家并简述核心推理路径
partial    得分率 50%-80% 时显示，指出方向对但证据链不完整
failed     得分率 < 50% 时显示，说明主要偏差来源（被哪条误导带偏/哪个矛盾没发现）
```

---

## 八、行动点上限（`actionPointLimit`）

建议值：
- 入门案：10
- 进阶案：12
- 高阶案：14

实际值根据节点数量和最优路径成本微调，确保玩家有 1-2 点容错余地。

---

## 九、红鲱鱼链（必填）

**每个精制案必须设计至少一条"完整但错误"的推理链。**

单点误导不够迷惑——玩家只要看到有"明显弱证据"就能排除。真正的挑战是：让错误答案也有 60-70% 的自洽性，直到玩家发现一条关键矛盾才能推翻。

### 红鲱鱼链必填格式（写在案件文件顶部注释里）

```
// ── 红鲱鱼链：[错误结论] ──────────────────────────
// 错误结论：玩家可能误判为……
// 支持它的表面证据：
//   - 证据 A（id: xxx）
//   - 证据 B（id: xxx）
// 解释不了的关键矛盾：
//   - 矛盾点 C（对应证据 id: xxx）
// 复盘拆解：先承认"为什么这条链看起来合理"，
//           再指出"在哪里断了"。
```

### 示例

```
// ── 红鲱鱼链：赵氏自尽 ────────────────────────────
// 错误结论：赵氏因情绪低落，自行上吊
// 支持它的表面证据：
//   - 旧白绫（id: old-rope）——家中常备旧物，取材方便
//   - 板凳倒地（场景）——符合蹬翻板凳的自尽动作
// 解释不了的关键矛盾：
//   - 双脚离板凳过远（id: feet-distance）——距离导致自尽动作物理上无法完成
// 复盘拆解：旧白绫和倒地板凳让人第一时间相信表面说法；
//   但双脚与板凳的距离排除了"蹬翻"这个必要动作，自尽链在物理上断了。
```

## 十、验收自查清单

填写完成后，**先过 `npm run check`，再过以下人工自查**：

### 数据完整性（`npm run check` 负责）

- [ ] `evidenceList` 中所有 `id` 唯一，无重复
- [ ] `investigationNodes` 中 `evidenceIds` 引用的 id 均存在于 `evidenceList`
- [ ] `requires` 中引用的节点 id 均存在于 `investigationNodes`
- [ ] `deductionSteps` 中 `correctOptionIds` 的 id 均存在于对应步骤的 `options`
- [ ] `deductionSteps` 中 `requiredEvidenceIds` 的 id 均存在于 `evidenceList`
- [ ] `feedback.optionFeedback` 覆盖所有步骤的所有选项 id
- [ ] `feedback.evidenceFeedback` 覆盖所有证据 id
- [ ] `feedback.missingKeyEvidence` 覆盖所有 key 类证据 id
- [ ] `initialHypotheses` 有 3 个选项

### 反猜答案人工自查

- [ ] 只看断案选项（遮住勘查内容），不能稳定猜出正确答案
- [ ] 只读勘查文本（不做断案），不能直接读到最终真相
- [ ] 错误选项都有至少一条表面合理的证据支持
- [ ] 正确选项没有比错误选项长一大截
- [ ] 至少有一条红鲱鱼链能让玩家认真犹豫
- [ ] 勘查 `result` 中没有"说明""即栽赃""真正目标""最可能""只有……才……"等结论性句式（知识节点除外）
